# 单入口 Native 方案：18 项暴露面审查

2026-11-02。目标：保持当前登录业务不变，核对真实痕迹，减少不必要组件，并为无法静态确认的权限和时序提供证据。使用 code-reviewer 与 software-security 流程审查。结论是有条件保留当前成功基线，不把本项目称为无痕、纯 Java 或已证明低检测率。

审查基线为用户已确认成功的原始 2.0.1 ZIP，SHA256 `51382311c68c344f8f0dba0689948e9b26a2c1ff2af7a38a8575eea666a6ad2e`；同时检查当前源码与静态 Dobby 归档。原成功包不修改。ADB 当前无设备，**没有采集手机实际 maps、线程或检测结果**。

## 判定口径

本项目在游戏私有 `libtolua.so` 的 protobuf 编码入口修改登录字段，再由游戏编码、签名、加密和发送；它不是 `SSL_read/write` 或 `send/recv` 网络 Hook。

“基础风控可能命中”仅回答相应读取/比较机制是否能观察到，不代表该游戏实际启用、常查或会处罚。表中“常查/进阶常查”没有本游戏 SDK、版本或实测依据，不能按行业统一频率采信。高/中/低描述条件成立时的暴露或兼容性重要程度，不是封号概率。

maps 可以显示地址、权限、偏移、设备/inode 与 backing 路径；匿名或特殊映射本身不是恶意结论。`mprotect` 作用于整个页，撤销执行权限时，同页并发执行可能触发 SIGSEGV。[Linux maps 文档](https://man7.org/linux/man-pages/man5/proc_pid_maps.5.html)、[mprotect 文档](https://man7.org/linux/man-pages/man2/mprotect.2.html)。

## 主要问题与最小修订

**高优先级保留项：**匿名可执行跳板、目标代码改写以及服务端识别能力仍存在。Dobby `CodePatch` 的权限设置缺少错误检查；没有把它当成已经被修好的问题。完整消除这些项需要重新设计/验证，不是改 SO 名、线程名或一条 mprotect 就能安全完成。

本轮只加入不改变过滤业务的修订：

1. 显式 linker 导出列表，只允许两个 Zygisk 入口；打包前检查无 W+X LOAD、无执行栈、无 TEXTREL、完整 RELRO、16KiB 对齐、无调试段及无额外依赖。这些约束防止后续构建回退；成功 2.0.1 本身已经通过同样的静态检查。
2. 安装完成后只读检查编码函数与原始跳板的 maps 权限，不输出地址/路径、不修改任何权限、不扫描/改写其他 JIT 页。`permissions=5` 表示 R+X，`7` 表示 R+W+X，`-1` 表示没取到结果。不能用这个安装后快照证明短暂 RWX 窗口不存在。
3. 记录 `hook_install_timing.duration_us`（DobbyHook 调用时长）与 `worker_completed.duration_us`（等待、安装及审计的工作线程总时长），线程在完成后退出。
4. 审计事件与业务状态分开，读不到 maps 或发现权限警告不会被 UI 误显示为未加载，也不会改变游戏登录结果。

**已保持的正确约束：**只改两个登录 protobuf 消息，原过滤器文件未改；不触碰公共库、GOT、TLS、资源版本和凭据；Root 内核/SELinux/日志缓冲参数不改；失败的旧方案不重新启用。

## 验证、证据与剩余工作

二进制证据见 `NATIVE-AUDIT-EVIDENCE-2026-11-02.json`。Dobby SHA256 为 `609ed766e94c21313a4373ed62a3b296bd12c8b4bfabfab4df19a611b0a38746`。权限枚举转换表为 `[0,1,3,7,5]`；AllocateCodeChunk 传枚举 4，对应 POSIX RX=5；OSMemory 使用 fd=-1 的匿名私有 mmap；CodePatch 依次传权限 7、5，反汇编未见检查 mprotect 的返回值。该结论针对现有归档，不能拿 [Dobby 上游当前源码](https://github.com/jmpews/Dobby)代替它的版本证据。

候选为 **2.0.2 审计诊断版**，原成功 2.0.1 仍是推荐使用版本。候选在电脑完成 ELF 策略正负测试、maps 行解析测试、控制/状态回归、真实 Lua/protobuf 过滤回归及安卓构建；未验收候选的手机启动、登录、对局或实际权限快照。

结论：本轮可以确认暴露面，不能确认本游戏风控检查频率、不会命中或“比 LSP 隐蔽很多”。无需要用户补充的业务问题；剩余运行证据只在设备可用时获取，不以新试装成功替代内存权限核对。
