# 与最初已可用的 LSP 0.4.1 比较

依据本仓库源码及本地归档 `minifire-compat-0.4.1` 核对。0.4.1 用户已验证苹果角色、对局、缓存重登和重启；2.0.1 于 2026-11-02 获用户跨区登录成功反馈；本轮没有独立 ADB 审核，也没有追加确认本版对局/重启。

| 项目 | LSP 0.4.1 | 单入口 Root 2.0.1 |
|---|---|---|
| 加载 | LSPosed 现代接口；需要游戏作用域 | Zygisk Next 公开 API；不需要 LSPosed 游戏作用域 |
| Java 层 | Application.attach 启动挂钩；两个 SDK 登录/返回观察挂钩（是否成功以运行阶段为准） | 无 Java Hook、无 DEX 注入、无 SDK 观察 |
| Native 层显式业务 Hook | luaopen_pb 引导、pb.encode 改写、pb.decode 登录返回码观察，最多三个入口 | 仅 pb.encode 一个入口；没有解码返回码观察 |
| 加载器处理 | 通过 LSPosed 原生库加载回调触发 | 有限时已加载库枚举线程；不 Hook dlopen/android_dlopen_ext；安装后线程退出 |
| 登录平台 | PhoneOs / Phone_Os → 2 | 相同 |
| 登录渠道 | ChannelID → 888，仅已知渠道接受 | 相同 |
| 登录版本 | 0.4.1 目标为 1.0.78 | 当前配置目标为 1.0.79；保留缓存混合版本处理 |
| 改写消息 | md.ApiLoginRequest、md.Login | 相同；直接编译复用同一份过滤器 |
| 签名/TLS/业务加密 | 交回原编码和网络链路 | 相同；没有自行解密网络或重新实现请求签名 |
| 启动资源版本、账号凭据 | 不改写 | 不改写 |
| 证书、网络规则 | 没有本项目代理 CA/重定向规则 | 没有本项目代理 CA/重定向规则；升级时清理旧 1.0.x 转发器 |
| 进程内可见内容 | LSPosed/模块 Java 类与原生库、框架钩子及业务跳板 | 一个本项目 Zygisk ELF（包含静态 Dobby/C++ 代码）、编码跳板与修改入口、启动时的配置快照；无传入游戏的私有文件 FD 或配置映射；Zygisk Next 自身行为另计 |
| 生命周期 | Native 编码 Hook 持续到游戏进程结束 | 同样持续到进程结束；开关变更在重开游戏后生效，不冒险实时移除正在运行的代码跳板 |
| 日志能力 | SDK 观察、登录编码和返回码观察 | 加载、校验、一个 Hook 安装、编码调用及登录字段改写；没有返回码 Hook，因此不能从“已改写”推断服务器接受或苹果角色已进入 |
| 当前验收 | 用户报告实机成功 | 用户已报告登录成功；对局和重启待本版追加确认 |

“显式业务 Hook 入口数量”不包含 LSPosed/Zygisk Next 框架自身的内部实现，不是整个手机的 Hook 总数。新方案减少了本项目的观察/启动入口和 Java 类，但仍能留下注入库、可执行跳板、函数入口变化和 FD 等可见内容。无法据此量化检测概率，也不保证更隐蔽、不封号或金融软件完全不受 Root/Zygisk 环境影响。

普通 Zygisk 模块会先参与框架的应用启动筛选；本模块对普通应用主进程通过 Root companion 做短暂选择握手；非所选应用返回不选中后卸载，对子进程、系统服务和隔离 UID 直接请求卸载；不安装业务 Hook，不传递私有文件 FD。这不等于 Zygisk 框架从未在其他应用的启动过程中执行过代码。

这里的“痕迹”与“隐私泄露”不同：本项目日志均不输出账户凭据；不往外上传诊断。2.0.1 不向游戏传递任何私有日志或配置文件 FD；配置在 Root 读取后以简单数值响应返回，握手日志由 Root 写入，运行日志由 Root 收集系统标签；不授予游戏 Root 身份。导出会把这些模块日志复制到 Download，用户可自行分享。
